# Проверка VK Donut

Это диагностический стенд, а не готовое приложение для подписчиков. Он выполняет только чтение VK API. Токен остаётся в памяти страницы, не сохраняется и не попадает в скачиваемый результат. Полные тексты постов не экспортируются.

## Запуск

1. Создайте VK Mini App в кабинете разработчика: https://dev.vk.com/ru/mini-apps/getting-started . Если приложение уже есть, используйте его тестовое размещение.
2. Разместите содержимое папки на HTTPS-хостинге как обычную статику. Нужны index.html, app.mjs, core.mjs и папка vendor. Сервер должен отдавать .mjs как JavaScript. Сборка и npm не нужны.
3. Укажите HTTPS-адрес index.html в настройках размещения приложения для нужных платформ.
4. Откройте https://vk.ru/appВАШ_ID . Стенд должен открываться внутри VK, а не напрямую по адресу хостинга.
5. Введите числовой ID тестового сообщества без минуса. При запуске из сообщества поле может заполниться автоматически.
6. Нажмите четыре кнопки по порядку. Для подписки сначала проверяется базовый токен; для чтения стены отдельно запрашивается wall. Если базовый токен не подходит, повторите проверку подписки после получения wall.

На стенде нет секретного ключа приложения: вводить его не нужно. Не публикуйте личные токены в коде. Стенд использует официальный VK Bridge 3.0.2, встроенный в архив. Лицензия находится в vendor/bridge_license.txt. API 5.199 — версия опубликованной схемы, а не утверждение о самой новой версии: поле можно изменить.

## Подготовка сообщества

- Сделайте несколько обычных и закрытых Donut-постов: текст, изображение, документ, видео, внешняя ссылка.
- Отдельно добавьте посты разных уровней, если уровни включены.
- Для пагинации нужен архив больше 100 закрытых постов. На маленьком архиве этот сценарий не проверен.
- Проверяйте под отдельными аккаунтами: администратор, активный дон, неподписчик. Выбор роли в форме — только подпись результата: он не меняет реальные права VK.

## Матрица реальных проверок

| Сценарий | Что проверить |
| --- | --- |
| Автор / администратор | Текст и вложения закрытых постов действительно возвращаются; заглушек нет; нужные исходные посты открываются. |
| Активный дон | donut.isDon и getSubscription согласуются с состоянием VK; возвращаются ожидаемые поля; доступные файлы открываются. |
| Другой уровень | Сравнить фактические ответы и наборы постов. Не считать сумму платежа идентификатором уровня без доказательства. |
| Неподписчик | Закрытый текст и вложения не возвращаются; ссылки на оригиналы не дают доступ. Ошибка метода отличается от ответа «не подписан». |
| Отмена автопродления | До окончания оплаченного периода доступ должен соответствовать VK. Повторно получить токен и проверить ответы. |
| Окончание периода | После фактического окончания оплаты повторно проверить ответы и доступ к оригиналам. |
| Продление | После успешного списания повторить проверку. Нельзя имитировать списание выбором роли. |
| Редактирование / удаление | Изменить или удалить тестовый пост в VK, заново выполнить импорт и сравнить ID, длину текста и вложения. |
| Большой архив | Лимит поставить выше числа закрытых постов. reason=end, partial=false; сравнить с VK. Если записи менялись во время импорта, повторить на неизменном архиве. |
| Устройства | Повторить на iOS, Android и компьютере, сохранить результаты отдельно. |

## Что означает результат

- placeholders > 0: как минимум часть закрытого содержания не получена.
- postsWithText и postsWithAttachments: фактические данные вернулись, но работоспособность файлов и видео проверяется отдельно по исходным ссылкам.
- partial=true: импорт ограничен, остановлен либо прервался. Это не успешный полный импорт.
- reason=end: пагинация дошла до конца ответа API. Это ещё не доказательство полноты относительно фактического архива VK.
- errors: смотреть код и текст. Отсутствие разрешения приложения — другой результат, чем отсутствие подписки пользователя.
- Поля подписки сохранены в исходном виде для проверки уровней. ID пользователя тоже может присутствовать: результат передавайте только тому, кому хотите его показать.

Скачайте результат каждого сценария кнопкой в стенде. Пока он не открыт в реальном VK-приложении с настоящими правами, интеграция с VK не проверена. Локальные проверки кода и имитация ответов не заменяют эту проверку.

Стенд не тестирует Callback API, серверную проверку подписи запуска, постоянную синхронизацию, платежи нашего сервиса, модерацию или спрос. Для выпуска настоящего кабинета они остаются отдельными задачами. На клиенте нельзя хранить импорт автора и считать проверку в интерфейсе защитой закрытого контента.
